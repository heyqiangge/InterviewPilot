# 面试讲解与高频考点

## 90 秒项目介绍（如实版）

“我做了一个面向后端岗位的个人项目 InterviewPilot，用来解决普通 AI 模拟面试跨轮不记得候选人、追问泛化、效果难评估的问题。后端使用 Spring Boot 和 H2 存会话与记忆，LangChain4j 接模型。每次回答后先按 0–4 分 rubric 评估，再只提取有原文证据的能力记忆；记忆按主题、重要度、时间和相关性召回，跟最近 4 轮原文和更早轮次摘要组合，同时检索后端知识材料生成下一题。项目可在无密钥的离线演示模式跑通，也有独立评测脚本计算四项指标。目前是 MVP，简历里的百分比是待验证目标，不是实测结果。”

## 很可能被追问的点

1. **为什么不用直接把所有历史聊天拼进 Prompt？** 长对话成本和噪声随轮次增长，容易丢掉关键旧信息。这里把最近 4 轮保留原文，较早轮次压成主题与分数摘要，跨会话只检索相关长期记忆；每次最多 5 条且限制事实长度。代价是摘要和记忆抽取会丢信息，所以需要 Recall@5 与错误注入率评测。
2. **记忆如何避免幻觉？** 模型抽取结果必须有 `sourceQuote` 且确实出现在本轮原回答中；字段长度、类别、置信度范围都校验；同主题相似事实合并。它只能阻止“无原文证据”的记忆，不能保证事实正确，需要人工标注和冲突测试。
3. **冲突记忆怎么处理？** 同主题、语义相近但 `strength/gap` 相反且新观察置信度 ≥0.8 时，旧记忆失效。当前相似度是词面近似，复杂语义冲突仍是已知局限；可进一步用结构化知识点 ID 与人工复核。
4. **RAG 的混合检索是什么？** 词面相似度适合索引名、TCP 术语等精确匹配；OpenAI embedding 相似度可召回改写说法；加上主题先验融合排序。目前只内置 7 段示例知识，不应称为生产知识库。真实扩展要做文档切块、版本、来源、去重、权限和引用溯源。
5. **为什么存被召回的记忆 ID？** 评测必须能复现“这个追问当时看到了什么”，否则只看最终问题没法区分召回错误与生成错误。`turns.retrieved_memory_ids` 是审计轨迹。
6. **四项指标怎么计算？** 记忆 Recall@5 按必需记忆 ID 计数；错误记忆误用按有禁止记忆机会的题目计数；追问相关性由独立人工标注；评分一致率按模型与人工 0–4 分相差 ≤1 计数。正式评测至少 50 组多轮样本，各项至少 20 个有效机会，报告置信区间。
7. **如何避免评分泄漏与自评自嗨？** 固定独立测试集、人工先盲标、分歧仲裁；不要让同一模型生成参考答案又自己判定正确；分层报告不同主题与难度，保留失败案例。
8. **并发与幂等？** 当前 `synchronized` 只处理单实例串行，重复提交仍可能生成两轮。生产化应给每次答题请求幂等键，在 sessions 表引入 version 并用乐观锁 CAS 更新当前题目。
9. **隐私与安全？** 本地服务只监听回环地址，公开仓库没有简历、候选人回答或密钥；没有账号认证，不可直接公网部署。Prompt 将回答/记忆/知识视为不可信数据，仍应增加敏感信息脱敏、保留期限、删除能力和注入对抗测试。
10. **性能怎么测？** 记录模型生成、embedding、数据库、召回各阶段耗时与 token/费用；测 P50/P95、失败率、单位面试轮次成本，再通过预计算知识向量、缓存查询和异步抽取优化。当前没有这些实测数字，不要声称已提升多少。

## 对照代码能讲清的取舍

- `InterviewEngine`：先落 turn，再抽取记忆，然后检索并生成下一题；为什么把模型调用包进事务是当前 MVP 的简化，未来应拆成状态机/Outbox，避免长事务。
- `MemoryManager`：证据门控、去重、冲突合并阈值如何调；用人工标注构建 precision/recall 评测。
- `Retriever`：词面 0.40/主题 0.20/向量 0.20/重要度 0.15/时间 0.05 是手工初始权重，不是训练得到的；怎么在验证集调优且防止测试集泄漏。
- `Gateway`：模型实现和编排解耦，离线模式可重复测试；OpenAI 模式要处理 JSON 解析失败、超时、重试与费用上限。
